## What it does
- **Lists** (`/wishlists`): lists bar (All saved + each list with its count), "New list" (max 20 per member, `LIMITS.maxLists`; names 1-60 chars, unique per member). `?list=<id>` shows one list with: Rename, Delete list (not the main list), per stay a note box (300 chars, blank removes it) and a "Move to" select. Without `list`, or with an id that is not the member's, every saved stay is shown once and read-only.
- **Delete list**: the stays are not lost, they move to the main list (a stay already there is not repeated, notes travel). If the main list would exceed 100 stays nothing is deleted (409). The main list cannot be deleted.
- **Move**: from one own list to another; if the target already has the stay it is only removed from the source; a full target (100) is a 409. `ListingStat.saves` is not touched (the stay stays saved).
- **Saved searches**: "Save this search" (name + the page's current filters, signed-in members, on filtered results) -> `POST /saved-searches`; page `/saved-searches` with a re-run link ("/listings?" + stored query) and Delete; max 20; name unique per member. **The stored query is built by the server** from the form's fields through `parseListingQuery` + `queryPairs` (known parameters, valid values, fixed order, no page, no `name`/`_csrf`), so nothing the browser sends is stored or redirected to as is. A search with nothing set is refused.
- Everything is the signed-in member's own: a list, stay or search that is not theirs is the same 404 as a missing one; ids from the URL, texts from the form, nothing else is read. Account deletion also deletes the member's saved searches.
