## The rules (each has its own message and code)
`check_out_not_after_check_in`, `check_in_past`, `check_in_too_far` (365 days), `below_min_nights`, `above_max_nights` (host value, never above 90), `over_capacity`, `advance_notice`, `same_day_cutoff`. Order of use: stay rules, capacity, then notice and cut-off (only when check-in is not already past/too far).
- **Advance notice:** hours from now to the check-in moment (check-in date + the listing's check-in time, both on the listing's clock). Exactly the notice is enough; one minute short is refused.
- **Same-day cut-off:** a stay starting today (listing's date) is refused once the listing's clock reaches the cut-off. When advance notice already refuses the date, only the notice message is shown.
- Clocks use the listing's `timezone`, not the server's. A wall-clock comparison is used (no daylight-saving correction): exact for Asia/Kolkata, off by at most an hour on a DST-change night elsewhere.
- Public API output names the capacity `capacity` (not `maxGuests`) because `api.availability.test.js` forbids the word "guest" in that JSON.

## Behaviour changes to know about
- Same-day bookings are refused from 20:00 (listing time) unless the host changes the cut-off (existing listings get the default). Before this task a same-day stay could be booked at any time.
- A replayed booking (same idempotency key) is still answered from the first reservation and is not judged again by new rules.
