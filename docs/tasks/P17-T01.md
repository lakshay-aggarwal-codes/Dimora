## What the test checks
1. **Coverage.** It wraps `express.application.use` while `createApp` runs, so it learns every router and the path it is mounted at, and reads each router's stack (`route.path`, methods, handlers). The app's own routes are read from `app.router`. A route without an entry, an entry without a route, a router nested inside a router (its mount path cannot be recovered), and a route registered twice all fail.
2. **Guards match the entry.** `public`: no `isLoggedIn`, no `authorize`; the only public routes that change data are `POST /signup`, `/login`, `/logout`. `login`: `isLoggedIn` is in the chain. `authorize`: `isLoggedIn`, then exactly one `authorize` whose action equals the entry's. `inline-login`: no guard in front (the handler answers 401). Everything under `/admin` is `admin`, nothing else is, the admin router starts with `adminGuard`, and every admin write is wrapped in `auditedMutation`.
3. **Behaviour.** Every non-public route is called anonymously through the real app (placeholders filled with a sample id; CSRF token supplied by the test agent): `login`/`authorize` -> 302 to `/login`; `inline-login` -> 401 JSON with code `unauthenticated`; `admin` -> 404. These requests never reach a database when the guard works; a missing guard shows up as a different status or a hung request.
4. The comparison function is itself tested with a fake missing and a fake stale route.

If the first run fails, the likely causes are (a) the way `app.all("/{*splat}")` or the array-path `app.post([...])` appears in `app.router.stack`, (b) a route registered that the text scan missed. The failure messages list the exact keys.

## Limitations
- Only the door is tested here; object-level access (is it your booking, your conversation) is in the policies, services and `authz.db.test.js`.
- A route whose guard is written inline in the handler cannot be told from a public one by looking at the stack; that is why `inline-login` is its own class and is proved by the anonymous request.
- Nested routers are refused rather than followed.
