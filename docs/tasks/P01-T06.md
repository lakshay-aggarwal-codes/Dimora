# P01-T06 — Repair listing page, map, seed data (Q10) — D-04, D-05, D-14

Date: 2026-10-14 · No new dependencies · No DB/config changes (`.env.example` unchanged).

## Root causes (docs/BASELINE.md)
- D-04: `show.ejs` used `<% - JSON.stringify(listing) %>` (emits nothing) and `map.js` read `listing.geomtry`; a naive fix would embed the whole document, including user text, in a `<script>`.
- D-05: the seed listings had no `geometry` (required by the model) and a hard-coded owner id; the page dereferenced `listing.owner.username`.
- D-14: `price` is optional in the model, but the page called `price.toLocaleString`.

## What changed
| File | Change |
|---|---|
| `views/listings/show.ejs` | Inline `<script>` removed. `<div id="map" data-token data-lng data-lat data-title>` is rendered only when the listing has valid coordinates, otherwise a short message. Owner name, price and image are null-safe (`Price not available`, placeholder picture, no "Owned by" line without an owner). Edit/Delete use a null-safe owner check. All values go through `<%= %>`. |
| `public/js/map.js` | Rewritten. Reads the data attributes, validates the numbers and range, builds the map and marker. The popup is built with DOM nodes and `textContent` (the old `setHTML` with the title was an XSS sink). Shows a message if Mapbox GL or the token is missing or Mapbox throws. No globals needed from the page. |
| `src/utils/geo.js` (new) | `toMapPoint(geometry)` returns `{lng, lat}` or `null` (wrong type, non-numbers, out of range). |
| `src/controllers/listing.js` | `showListings` passes `mapPoint` next to `listing`. |
| `scripts/seed-data.js` | Every one of the 29 listings has a hard-coded `geometry` Point (approximate centre of the named place, `[lng, lat]`). No Mapbox key needed. |
| `scripts/seed.js` | Rewritten. Loads `.env`, refuses when `NODE_ENV=production`, reads `MONGODB_URI` (`ATLASDB_URL` still accepted), creates the demo host `dimora_demo_host` (random password printed once, only when created), validates all 29 documents with the model before writing, upserts by `(owner, title)` (idempotent, keeps existing reviews), `--reset` deletes only the demo host's listings and the reviews on them, then re-creates them. Exports its helpers; runs only when executed directly. |
| `eslint.config.js` | The documented exception for `map.js` (inline globals, unused vars) is removed; only the `mapboxgl` global remains. |
| Tests | `tests/unit/geo.test.js`, `tests/unit/seed.test.js` (29 valid documents, unique titles, geometry range, guards, production refusal by running the script), `tests/unit/mapScript.test.js` (runs `map.js` in a Node `vm` with fake DOM and Mapbox), `tests/integration/listings.show.test.js` (real app and views, `Listing.findById` stubbed: no owner, no price, no image, no geometry, escaped title, no inline listing data), `tests/integration/listings.show.db.test.js` and `tests/integration/seed.db.test.js` (database-backed). |

## Behaviour changes
- `npm run seed` no longer wipes everything: it adds/refreshes the 29 demo listings and leaves other data alone. Use `npm run seed -- --reset` to rebuild the demo host's listings.
- The seed no longer needs Atlas/localhost hard-coding; it uses `MONGODB_URI`.
- A listing without coordinates shows "The map is not available for this listing yet." instead of an empty box.

## Verification
- Executed: `node --check` on every changed or new JS file (all clean).
- Executed with a tiny stand-in runner (not Jest): `tests/unit/geo.test.js` and `tests/unit/mapScript.test.js`, 25 checks passed. Plain-Node check of `scripts/seed-data.js`: 29 entries, 29 unique titles, every `geometry` a Point in range.
- Executed: a structural check that the scriptlets of `show.ejs` form valid JavaScript (templates were not rendered).
- **Not executed:** `npm run lint`, `npm test` (Jest), Prettier, any EJS rendering, the seed against a database. The sandbox has no network, so `npm ci` could not install dependencies. The new tests that need `mongoose`, `ejs`, `supertest` or a database are written but have never been seen to pass.

## Owner steps
1. `npm test` (first run may fail only if something above is wrong; paste the output if so), then `npm run lint`.
2. Seed a **development** database: `npm run seed`. Expect "29 created", the demo host password printed once. Run it again: "0 created, 29 already present".
3. `npm run dev`, open `/listings`, then a few detail pages: each loads, the map shows a red marker, the popup shows the title and "Exact location after booking".
4. Open a listing, view page source: there is no `<script>` with listing data, only the `#map` div with `data-*` attributes.
5. Optional: set `NODE_ENV=production` in the shell and run `npm run seed`: it must refuse.
