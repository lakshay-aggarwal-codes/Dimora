## Behaviour
- **Summary:** users by status + active admins; listings by status (a listing its host deleted is not counted); reservations by all 7 statuses; open reports. Read live on each visit.
- **Lookup:** `q` as a 24-character id matches that reservation or every reservation of that guest, host or listing; any other text matches guests (username, email, display name) and listing titles, case-insensitive, as plain text (regex characters are escaped). At most 50 guests and 50 listings feed one text search; the page says when that cut applied. Status filter, 20 per page, newest first.
- **Detail:** people (links to the admin user/listing pages), stay, price snapshot, refund record, cancellation reason, status history. Every value escaped. No form, no button, no POST route; reading writes no audit row (tested).
- **Audit filters:** action exact or prefix (`user.` matches `user.suspend`, `user.make_admin`); admin username (case-insensitive) or the label of a script such as `cli:make-admin`; target type; UTC `from`/`to`, both inclusive. A value that is not valid (bad date, pattern characters in action, unknown target type) is ignored, not an error.
