## Decisions and deviations
- **`vibe` did not exist.** The card says categories map to "real `propertyType`/`vibe` values from the listing model", but the model only had `propertyType`. I added an optional `vibe` rather than guess a mapping from titles. Hosts choose it in the basics step. Old listings have none, so they show under no setting category until edited (no migration; nothing to infer from).
- **Categories without data were dropped**: Trending, Castles, Tiny Homes, Historical Homes, Skiing, Design, Camping, Arctic (no field says so). "Mountains", "Beaches", "Farms" etc. were renamed to the slugs above. Old `?category=beaches` links now get the "not one of the choices" message and show everything.
- One category at a time. It is combined with the panel by AND, so Farm stays + type Villa is empty by design.
- The panel is `<details>` + a GET form rather than an off-canvas drawer: it needs no JavaScript and no Bootstrap JS. It shows no per-option result counts.
- `minRating` and `sort` stay as before: validated, kept in links, no panel control and no effect (ratings P12-T02, sort see below).
- **Task 37 (P05-T03) is not applied on this repo.** `docs/tasks/P05-T03.md` exists and `src/services/search.js` has `searchPage`/`sortSpec`, but `GET /listings` is served by `src/controllers/search.js` (task 36), which sorts newest first and has no sort links or "page does not exist" state; `tests/integration/listings.results.test.js` and `search.paging.db.test.js` therefore describe behaviour the page does not have. `PROGRESS.md` has no Q37 row. I did not wire it in here (one task per run); the next step before task 39 should be re-running task 37 on this repo. The panel and chips already carry `sort` and `page` correctly, so it will fit.

## Owner steps (browser)
1. `npm run seed` (adds `vibe`, type and amenities to the 29 demo listings), then open `/listings`.
2. Click each category: only matching stays show, the chip row shows the category, the strip marks it. "Farm stays" and "Rooms" are empty on the demo data (no demo listing is one) and show the empty state with the "Remove the filters" link.
3. Open Filters, set a price range, two property types and an amenity, press Show stays: chips appear for each, the Filters button shows a count, clicking a chip removes just it. Reset filters keeps your destination and dates.
4. With JavaScript off the same steps work (the panel is a plain form).
5. Edit one of your own listings: the basics section has "Setting (optional)"; set "Beach" and check it appears under Beach.
6. At 360 px wide: the strip scrolls sideways, the panel fields stack, no sideways page scroll; check keyboard focus on the chips and the Filters toggle.
7. Try `/listings?category=beaches` (old link): a message says the category is not one of the choices and all stays show.

## Limitations
- Listings created before this task have no `vibe` (and old-form listings no `propertyType`): they match no category until the host edits them.
- The category rules run on `vibe`, `propertyType`, `roomType`, `amenities` without a dedicated index; fine at this size, left to P18-T02.
- No result counts per category or per option; the empty-state suggestions are P05-T05.
- Loading state is a dimmed results area and a status message, not a skeleton.
