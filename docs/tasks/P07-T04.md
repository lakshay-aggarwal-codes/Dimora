## API contract
`GET /api/listings/:id/availability?from=YYYY-MM-DD&to=YYYY-MM-DD` (`from` included, `to` excluded)

```json
{ "from": "2026-11-01", "to": "2026-12-01",
  "unavailable": ["2026-11-03", "2026-11-04"],
  "rules": { "today": "2026-10-20", "earliestCheckIn": "2026-10-20", "latestCheckIn": "2027-10-20", "minNights": 2, "maxNights": 14 } }
```
- Only dates: no guest, reservation, source or block information. A reservation, a live hold and a host block are indistinguishable; an expired hold is free. `Cache-Control: no-store`.
- Nights before today and nights past the last possible stay (latest check-in + 90) are not queried and never reported.
- 400 JSON for a missing, malformed, repeated or object-valued `from`/`to`, `to <= from`, or a range over 400 nights.
- 404 JSON for an unknown or malformed id, and for a draft, unpublished or deleted listing, except that the host (`listing:edit`) can read their own draft/unpublished listing (the owner's `?preview=1` page needs it).
- Not rate limited (one indexed read per call).

## Picker behaviour
- Own implementation, no library (flatpickr could not be installed or its keyboard behaviour verified offline; a library is also a new CDN script host in the CSP). Day numbers and integer calendar arithmetic only: no `Date` is built from a string (the `noUserDate` scan covers `public/js`).
- Keyboard: Tab into the grid; arrows move by day/week; Page Up/Down change month; Home/End jump within the week; Enter/Space picks. Unavailable days stay focusable (so the reason is announced) but have `aria-disabled` and cannot be picked. Status and summary are `aria-live`.
- Rules enforced client-side: past days, beyond 365 days ahead, taken nights, minimum and maximum stay. A check-out may fall on a taken night (not slept in). A check-in with no room for the minimum stay is disabled.
- Mobile: one month below 768 px, two from 768 px. Each month is fetched once per month and cached; a failed fetch shows a message and leaves days disabled.
- Fires `dimora:dates-change` (`checkIn`, `checkOut`, `nights`) on the picker element and fills two hidden inputs `checkIn`/`checkOut`, for the quote panel (P08-T02).
- Nothing is booked from this page yet.

## Limitations and deviations
- Listing time zone is fixed to `Asia/Kolkata` (there is no per-listing zone); host advance notice and same-day cut-off are P07-T06.
- `stayProblems` is not called by any route yet (no booking endpoint exists); it is the server-side re-validation the card asks for and is covered by unit tests.
- Roadmap said "flatpickr or similar via CDN": replaced by an in-repo script (see above).
- The `ledger.unavailableDates` and API reads are not atomic with booking: a guest can still lose a race, and booking (P07-T05) re-validates through the ledger.
