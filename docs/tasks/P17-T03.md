## The journeys
1. **Search, book instantly, trip page.** Sign in, search "Panaji", open the instant listing, choose dates (via `?in=&out=`, which the date picker reads), wait for the live price, Reserve, "Confirm booking", land on `/trips/<id>` showing the title and "confirmed"; it is listed under `/trips`.
2. **Request, host accepts.** Guest "Send request"; a second browser context signs in as the host, accepts on `/host/reservations`; the guest's trip page then says confirmed.
3. **Review after completion (time injected).** Instant booking for dates 30 days away; no review section before the stay; `POST :3101/complete-stay` moves the booking into the past and runs the real sweeper once (`createSweeper().runOnce`), which completes it; the guest reviews (5 stars, comment) and it shows on the trip and on the public listing.
4. **Host wizard.** Sign in as host, walk `/host/listings/new` step by step (fields are filled by id only when empty; the photo step uploads a 1x1 PNG, Cloudinary replaced), publish, see the public page, find it in search.
5. **Cancellation: `test.fixme`.** See below.

## Deviation: cancellation cannot be tested
In this repository the guest cancel path is missing, although task 54 is marked done:
- `src/routes/trips.js` registers `POST /trips/:id/cancel` with `controller.cancel`, but `src/controllers/trips.js` has no `cancel` (the request would fail with a server error).
- `views/trips/show.ejs` has only the cancellation *terms*; no cancel button, refund preview or confirmation dialog. `views/host/reservations.ejs` has no cancel control either (only the host route and `cancelBooking` exist).
The journey is therefore `test.fixme` with this reason. A repair task (restore `trips.cancel` + the two cancel sections from P09-T03) is needed first; then remove `fixme` and finish the test (cancel, check the refund line, check the nights are free again).

## Limits and notes
- "Time injected" is done by the test server only: it rewrites one booking's dates and runs the sweeper. Nothing of it exists in the app, and the control port listens on 127.0.0.1 only.
- The journeys use dates 10, 20 and 30 days ahead so they never share nights; the order does not matter.
- Browser-side behaviour of the date picker is bypassed on purpose (dates arrive through the URL); the picker itself has its own unit tests.
- Mapbox GL maps are not exercised (no token); the geocoder is replaced.
