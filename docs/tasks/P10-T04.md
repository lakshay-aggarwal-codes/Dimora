## Behaviour
- Owner, on a list's page: "Create a share link" -> `POST /wishlists/:id/share`; the page then shows the full link (read-only input) and "Stop sharing" -> `POST /wishlists/:id/share/revoke`. Any list can be shared, including the main one. Asking twice gives the same link (an atomic update only sets the token if none exists).
- Public `GET /shared/lists/:token`: list name, "shared by <display name>", and the stays that are still public as the usual cards. Opening it changes nothing; the heart on a card sends a visitor to log in like anywhere else.
- **Never shown**: the owner's email, username, id or profile link; the owner's notes; when stays were saved; other lists; stays that were hidden, unpublished or deleted (only counted: "N stays are no longer available").
- **404, always the same**: unknown, malformed (not 32 URL-safe characters), revoked, a list whose token was removed, an owner who is suspended or deleted. Deleting the list or the account removes the link with it.
- **The link is the credential**: response headers `X-Robots-Tag: noindex, nofollow`, `Cache-Control: private, no-store`, `Referrer-Policy: no-referrer`.

## Limits
- The token is stored in the clear (so the owner can copy the link again). Anyone with database read access could open shared lists; they only show public listings. Hash it (and show the link once) if that matters.
- No rate limit on `/shared/lists/:token` beyond the 192-bit token; the app-wide limits apply.
- A shared list shows the display name of the owner, which is already public on profile pages; there is no option to hide it.
- The link cannot be set to expire; revoke it by hand.
