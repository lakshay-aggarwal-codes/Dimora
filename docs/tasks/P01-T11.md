## Behaviour
- Files: `scripts/migrations/NNN-short-name.js` (3+ digits). Any other `.js` file in the folder is an error (catches typos). Sorted by number; duplicate numbers are an error.
- `up(db, ctx)` gets the native Mongo `Db` and `ctx = { dryRun, log }`; it returns an object of counts, which is logged and stored.
- `schema_migrations` document per migration: `_id` (file id), `name`, `checksum` (SHA-256, CRLF normalised so Windows and Linux agree), `status` (`running` → `applied`), `startedAt`, `appliedAt`, `durationMs`, `result`.
- "Refuses to run twice": a migration's record is inserted (`status: "running"`) before `up` runs; `_id` is unique, so a concurrent or repeated run gets a duplicate-key error reported as "already applied or being applied". A normal second run prints "Nothing to do" and exits 0 (`npm run migrate` is idempotent).
- The run stops, before running anything, when history and files disagree: applied file edited (checksum), applied file missing, new migration numbered below an applied one, or a record stuck in `running` (interrupted run; the message says how to clear it).
- If `up` throws: its `running` record is deleted, nothing later runs, the error says it was not recorded. Earlier migrations stay applied.
- `--dry-run`: still validates history, then calls `up` with `ctx.dryRun = true` and a read-only proxy of the db that throws on writes (insert/update/delete/replace/bulk/index/drop/rename, db-level create/drop/command, `aggregate` with `$out`/`$merge`). No `schema_migrations` write, not even creating the collection.
- Connection: `MONGODB_URI` (legacy `ATLASDB_URL`), optional `DNS_SERVERS`, like `server.js`/`seed.js`. Prints only the database name. Unknown arguments are an error. Exit code 1 on any failure.
- Allowed in production (migrations must run there); no confirmation prompt.
