## Behaviour
- **Pending** (all `pending` bookings of this host): soonest hold deadline first; the first countdown is rendered by the server ("5 h 12 min", "by 24 Oct, 11:30 am") and the script updates it every 30 seconds; at zero the buttons are disabled with a note. A request whose hold already ran out (sweeper not yet run) is listed without buttons.
- **Confirmed**: confirmed stays whose check-out is after today, soonest check-in first, each with a link to the booking page.
- **Guest summary:** display name (escaped), "member since Mon YYYY", and the number of completed stays of that guest with this host (one grouped query for the whole page).
- **Accept:** needs the listing to exist, not be deleted and not be `suspended` (409 `listing_suspended`; a listing the host merely unpublished still honours a request). Then `transition(..., "confirmed", {actor:"host", by})`: the hold is removed and the nights stay in the ledger. An expired hold gives 409 `hold_expired`.
- **Decline:** always possible while pending. Optional reason, trimmed, at most 500 characters (longer is a 400, never cut), kept in the status history `note`; nights are released.
- **Races:** accept, decline and the guest's cancel at the same moment: exactly one succeeds, the others get a 409 naming the status that won (tested with the fakes, and by the compare-and-set of T05).
- **409 handling in the browser:** the inbox is shown again with status 409 and the message in a red alert, so the host sees the current state.
- **Who may answer:** the booking's host. The guest, another host, an admin, a suspended host, a signed-out visitor, a missing booking and a malformed id all get the same 404 (no database read for a malformed id).
- Everything from guests and snapshots is escaped (tests with markup in the guest's and the listing's names).

## Limitations
- No email or in-app notice to the guest when a request is answered (notifications are P11); the guest sees the result under Your trips.
- Lists show the first 50 of each kind and say so; there is no paging or search yet.
- "Guest total" is what the guest pays, not the host's payout (no payout logic exists).
- Cancelling a confirmed stay is P09-T03.
- The countdown uses the visitor's clock; a wrong clock only changes the display, the server decides.
