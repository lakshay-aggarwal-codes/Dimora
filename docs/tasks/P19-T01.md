## How the documents are kept true
Documentation that is only written goes stale, so the checkable parts are checked by `npm test`:
- **Routes**: `docs/API.md` must list exactly the routes the app serves (a missing one, an extra one, a duplicate), each with the right "who" (admin / signed in / anyone, from the guard in the code), every `/admin` route as admin, the JSON routes as exactly the `/api` ones, and the route count quoted in the README. Every router file must be mounted.
- **Environment**: the README's keys equal the keys `src/config/env.js` reads, `.env.example` has all of them, a key the README calls required really makes the settings check fail when missing, and the defaults it states (port 8080, sweeper 60 s, review window 30 days) are the code's. The legacy names it mentions are still accepted.
- **Scripts**: the table equals `package.json` `scripts`.
- **Facts**: Node version = `engines`; "29 sample listings" = the seed data; the demo host's username; "90 days" and "24 hours" = the sweeper's defaults; every relative link exists.
- **Diagrams**: there are two (flowchart, entity diagram); the entity diagram has every model and a relationship for every reference the schemas declare (it found one missing on the first run: who creates an availability block).
- **No secret, no invented address**: patterns for connection strings with a password, Mapbox tokens and a GitHub address are refused.
Each check was proven to fail by breaking its fact once (a route row removed, a "who" changed, an environment row removed, a relationship removed, a script renamed), then restored.
