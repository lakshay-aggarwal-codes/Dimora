## The problems found
1. **Search with dates read the whole night ledger.** "Which listings have a taken night in this range" has no listing in the filter; the ledger's indexes all start with something else. Fixed: `date_1_listing_1_holdExpiresAt_1`, and the two ledger queries (`unavailableListingIds`, `unavailableListingIdsFlexible`) now ask for only those fields with `_id: 0`, so MongoDB answers them from the index without reading documents.
2. **The search orders, the home page and the map ("anywhere") sorted all published listings in memory.** Four indexes now deliver each order (`status` first, `_id` last as the tie-break): `status_1_ratingAvg_-1_ratingCount_-1__id_-1`, `status_1_createdAt_-1__id_-1`, `status_1_pricing.nightlyMinor_1__id_1` (also read backwards for price descending), `status_1__id_-1`.
3. **The host inbox sorted in memory**: `host_1_status_1_holdExpiresAt_1__id_1` (pending) and `host_1_status_1_checkIn_1__id_1` (confirmed). The queries now come from one exported function, `inboxQueries`, used by the service and by the review, so they cannot drift apart.
4. **The audit page sorted the whole audit log.** It sorts on `createdAt` and `_id`; the index had only `createdAt`. New index `createdAt_-1__id_-1`. (The checker found this one on its first run.)
5. **Reporting a review scanned every listing** (`Listing.findOne({ reviews: id })`, no index). `describeTarget` now reads `review.listing` and only falls back to the scan for an old review without one.

Dropped (nothing uses them; each costs a write on every insert/update): `status_1_address.city_1`, `pricing.nightlyMinor_1`, `host_1_status_1`, and the audit log's `createdAt_-1`.

## Migration 010
Adds 8 indexes (`createIndex` with fixed names: running it again is a no-op) and then drops 4 (only if present: MongoDB's "index not found" is ignored, any other error stops it). `down` brings the old four back and drops the new eight. The models declare the same names, so a fresh database gets them from Mongoose; **an existing database needs `npm run migrate`** because Mongoose creates missing indexes but never drops old ones. Building the new ones on a large live collection takes a moment; at this scale it is instant. `tests/unit/queryPlans.test.js` checks that the migration and the models agree, name by name and key by key.
