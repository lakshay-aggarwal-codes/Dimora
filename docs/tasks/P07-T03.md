## Behaviour
- Dates: strict `YYYY-MM-DD`; "first night" and "last night" are both included (`to` = last + 1). Today is the listing's time-zone date. Past nights cannot be changed; the last night is at most today + 365 d (≤ 366 nights).
- Block: nights already blocked by the host are skipped (and counted); a night held by a reservation or a live request hold → 409, nothing blocked. A guest winning a race between check and insert gives the same 409 and the partial rows are rolled back. Block rows are created before the note record; if the record fails, the nights are released. A crash between the two leaves ledger rows without a record: shown as a block with no note, and for the P07-T07 orphan sweeper.
- Unblock: only block rows in the range; a block with no nights left loses its record; a partly freed block keeps its record (the ledger decides what is blocked).
- Drafts are sent to the wizard, suspended listings to the status page, deleted/unknown listings are 404; a non-owner (admins included) gets 403.
- Page: no JavaScript needed; every night's state is text (hidden full date + visible "Blocked/Reserved/Request"); today has `aria-current="date"`; all user text escaped; errors re-render with 400/409 and keep the typed values.

## Limitations
- Reserved nights show no guest name/link (no Reservation model yet); click-through comes with P09-T02/P13-T02. Pending requests show as "Request" from `holdExpiresAt`.
- No JavaScript date selection: the host types or picks dates in the forms.
- The block list shows the next 400 days (first 100 stretches).
- Look at the page in a browser at 360/768/1280 px (grid scrolls sideways inside its box under 28 rem).
