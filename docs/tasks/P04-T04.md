# P04-T04 - Edit with location confirmation (Q31)

Date: 2026-10-17 - Deps: P04-T02 (Q29), done. No new dependency, no migration.

## What changed
| Item | Notes |
|---|---|
| `src/controllers/sections.js` | `renderEditForm` (a draft goes to the wizard) and `save` for `PUT /listings/:id/sections/:key`, key one of `basics`, `location`, `details`, `pricing`; anything else is a 404. Validates with the wizard's schemas (`src/validation/wizard.js`), applies with `wizard.applyStep`, saves, flashes "Changes saved." |
| Location | If the address differs from the stored one (or there is no stored point) it is looked up (`lookupAddress`), the page `listings/confirm-location.ejs` shows what was typed and Mapbox's name for the match, and nothing is saved until the "Yes, this is the right place" box is ticked. Not found -> message on the edit page; outage -> "try again" (503), error text not shown. |
| `src/services/locationConfirm.js` | The looked-up point is kept in the session with a hash of (listing, address) and a 15-minute limit; the confirm form carries the address only. A confirmation for another address, another listing, an expired or already used look-up is not accepted and simply looks up again. |
| `src/services/geocoding.js` | New `lookupAddress` (geometry + `placeName`); `geocodeAddress` is unchanged for callers. |
| Views | `views/listings/edit.ejs` rebuilt (section navigation, one form each, photo manager last, banner when the address was only guessed); `views/host/fields/*.ejs` hold the field markup shared with the wizard steps. |
| Routes | `src/routes/listing.js`: the edit route now uses the new controller; the section route is added. `listing.js` controller lost `renderEditForm`. |
| Tests | New: `locationConfirm`, additions to `geocoding`, `listings.sections.db` (real MongoDB). Updated: two edit-view tests in `pages.responsive`. |

## Decisions
- The same schemas as the wizard, so a published listing cannot be edited into a state the wizard would have refused (price under INR 100, min nights above max, and so on). The roadmap's "re-run readiness" needs the readiness service of P04-T05; until then this is the check.
- The street address stays out of the public `location` text (city and state only), as in the wizard.
- No pin yet: "display result text and require a confirm checkbox", as the card says, until P06-T03.

## Limitations
- `PUT /listings/:id` (the old single form: title, description, location text, price, one image) still exists because older tests use it; no page links to it. It re-geocodes without the confirmation step, so it should be retired with the old create form (P04-T05 or later).
- Reservations do not exist yet, so "capacity and minimum stay changes apply to future stays only" has nothing to protect; revisit in P07-T05.
