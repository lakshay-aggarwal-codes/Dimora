# P18-T03 - Accessibility audit and fixes (Q80)

Date: 2026-10-25 - **New dev dependencies: `axe-core` ^4.14, `jsdom` ^26.1** (run `npm ci`) - No migration, no application behaviour change except the fixes below.

## Why these two dependencies
The card asks for axe on every page type. axe needs a DOM: jsdom provides it without a browser or a database. jsdom 26 is the newest line that supports the project's `engines` (Node >= 20.19); jsdom 30 needs Node 22.22+. Both are used only by tests. See `docs/ACCESSIBILITY.md` for what the tests cover, what they cannot judge (colour contrast needs a layout engine, so it is computed from the design tokens instead), and the manual checklist.

## Findings fixed
1. `views/partials/nearby-status.ejs` and `views/compare/index.ejs`: an EJS comment containing `<%= %>` ends at its first `%>`; the pages failed with "Could not find matching close tag" (the status page of a published listing, and the whole comparison page). Comments rewritten; six failing tests pass again; the new compile test prevents a repeat.
2. `views/conversations/show.ejs`: `role="log"` moved from the `<ol>` to a wrapper so the messages stay list items.
3. `views/includes/navbar.ejs`, `views/pages/home.ejs`, `views/admin/users.ejs`: the three search landmarks have distinct names.
4. `public/js/date-picker.js`: focus stays on the month button after a redraw (or moves to the other when the pressed one is disabled); each day's spoken name starts with the weekday; the column headers carry the full day name.

## Commands run and results
- ESLint on `src`, `tests` and the changed script: nothing new (3 errors remain that were in the repo as uploaded: duplicate key `nearby` in `src/models/listing.js`, a control-character regex in `src/services/nearby.js`, an unused variable in `tests/integration/compare.routes.test.js`).
- Jest 30, `SKIP_DB_TESTS=1`: the 259 new tests pass. Whole suite: 3784 passed, 32 failed, 478 skipped; the repo as uploaded had 38 failing, so six are fixed and none is new.
- **Not executed:** a real browser, a screen reader, zoom/reflow and touch checks, the map, the photo viewer (jsdom has no `<dialog>.showModal`), and every database suite.

## Limitations
- Passing axe is evidence, not proof: about a third of WCAG needs a person (reading order, meaningful link text, error recovery, cognitive load). The checklist in `docs/ACCESSIBILITY.md` is what to do by hand.
- The notification count in the header changes without an announcement.
- The pages are audited with realistic view models, not with every possible data combination.
