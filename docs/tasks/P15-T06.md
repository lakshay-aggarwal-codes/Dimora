## What was built
- Rules: `src/config/purposes.js` (3 purposes, positive whole-number points over listing facts: amenity, room type, min bedrooms, min guests, instant book). Frozen.
- Ranking: `src/services/purposeRank.js` scores in JavaScript on a small projection of the best 2,000 matches (normal order), stable-sorts by score, cuts the page, loads that page's documents. Chosen over a Mongo `$addFields` score because `aggregate` does not cast the filter and a second definition of the rules would have to be kept equal.
- URL/UI: `purpose` param (validated like `sort`, in the link order after `sort`), "Plan for" bar, "how the stays are ordered" box with the rules and, when not acting, the reason (other sort order, or search words).
- Metric: `ListingStat.ranking.{default,work,family,weekend}.{shown,clicked}`; `src/services/rankingStats.js`; card links on Best-match pages carry `?from=<ordering>`; the listing page counts a click once per stay per session; `npm run report:ranking`.
