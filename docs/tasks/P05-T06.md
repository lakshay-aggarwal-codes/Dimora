## What it does
- `GET /api/destinations?q=<text>` returns `{ suggestions: [{ label, dest, count }] }`, at most 8, from stays that are published and not deleted.
  - one word: cities or countries that start with it; `"city, st"`: that city in a state starting with `st`; a third part narrows by country.
  - Same normalisation as the search itself (`normaliseToken`, accents and case ignored), so what is suggested is found by the search. `dest` is the host's wording when it normalises to the stored keys, otherwise the keys (same rule as P05-T05).
  - Under 2 letters, a missing, repeated or object-shaped `q`: `{ suggestions: [] }`, no database query.
  - Rate limit 120 a minute per IP; answers cached privately for 30 s. No third party.
- `public/js/destination-autocomplete.js` turns inputs marked `data-destination-autocomplete` into an ARIA combobox (navbar search, `/listings` "Where to?" field). 250 ms debounce, stale requests aborted, answers for old text or an unfocused box ignored, options built as text (no HTML), mouse pick on mousedown, arrows wrap, Enter picks only a highlighted option (otherwise the form submits as before), Escape closes, a polite live region announces the count. Without JavaScript or `fetch` nothing changes.

## Limitations and open points
- Query: `$or` over `cityKey` / `countryKey`, each prefixed by `status: "published"`, which the `status_1_cityKey_1_…` and `status_1_countryKey_1_…` indexes can serve. Not confirmed with `explain()`; add the query to `scripts/explain-queries.js` and read the plan on a real database.
- State names are not suggested on their own (`stateKey` has no index); a state is matched only as the second part ("panaji, g").
- Listings without `cityKey` (old data not migrated) are never suggested.
- The home hero field (`name="search"`) is not enabled: that parameter is the older free-text search, not the destination filter.
- Counts are of public stays, not of stays free on the chosen dates.
- The list is attached to `<body>` and placed from the input's position when it opens; it is not repositioned while the page scrolls inside a scroll container.
- Needs a manual pass: screen reader (NVDA/VoiceOver), keyboard only, 200% zoom, forced-colours mode.
