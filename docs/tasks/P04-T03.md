## What was added
| Item | Notes |
|---|---|
| `src/services/images.js` | `assertValidImage` / `detectImageType`: the file's first bytes decide (JPEG, PNG, WebP); the name and the type the browser claims are ignored; max 5 MB. `addImages`: up to 10 photos, every file checked before any upload, uploads in parallel, **all or nothing** (if one upload fails the others are deleted again; if the save fails every upload is deleted). `removeImage` (save first, then delete from Cloudinary; a published listing keeps one photo), `reorderImages` (must list every photo exactly once), `moveImage`, `setCover`, `updateImageText` (alt up to 200 characters, caption, control characters stripped), `replaceCover` (the old single-photo field), `galleryOf` (what pages show). A listing that only has the old `image` field gets that cover adopted into `images[]` before any change. The old `image` field is kept as a mirror of the cover. |
| `src/config/cloudinary.js` | Uploads pass `allowed_formats: ["jpg","png","webp"]` and `resource_type: "image"` (Cloudinary refuses anything else too). The multer type filter (declared MIME type) is removed: it proved nothing. New `uploadPhotos` (up to 10 files) and exported `uploadBuffer`. |
| `src/utils/imageUrl.js` | `imageUrl(url, preset)`: presets `card` (`w_800,f_auto,q_auto`), `thumb`, `full`, `edit`. Only `https://res.cloudinary.com/<cloud>/image/upload/...` URLs are changed, never twice. Registered as `app.locals.imageUrl`. |
| `src/routes/images.js`, `src/controllers/images.js` | `POST /listings/:id/images`, `PUT .../order`, `PUT .../:imageId` (alt/caption), `PUT .../:imageId/cover`, `PUT .../:imageId/move`, `DELETE .../:imageId`. Owner only (`isLoggedIn` + `authorize("listing:edit")`), CSRF (multipart form: token in the URL). Problems the host can fix come back as a message on the edit page; real errors go to the error page. |
| `src/middleware/listing.js`, `src/routes/listing.js` | `verifyUploadedImage`: the old create/edit forms now also check the real bytes before geocoding or uploading. The old edit field replaces only the cover and keeps the rest of the gallery. |
| `src/middleware/errors.js` | A too-many-files upload gets its own message. |
| Model (`src/models/listing.js`) | Photo shape `{ _id, url, publicId, alt, caption, order }` (was `{ url, filename, caption, order }` without `_id`). |
| `scripts/migrations/004-listing-images-v2.js` | `filename` -> `publicId`, adds `_id` and `alt`, sets `order` to the position. Safe to repeat, dry run supported, manual `down`. Documented in `docs/MIGRATIONS.md`. |
| `views/partials/gallery.ejs`, `public/js/gallery.js` | Detail page: cover, thumbnails, "Show all N photos". Every photo is a real link (works without JavaScript); with JavaScript it opens a `<dialog>` viewer: Enter opens, Left/Right arrows or Previous/Next move, Escape or Close leaves, focus returns to the photo you opened, live counter and caption. Alt text is the host's, else "<title>, photo 2 of 5". |
| `views/partials/photo-manager.ejs` | Edit page: per photo alt text, caption, Move earlier/later, Make cover, Remove (confirmation dialog), plus a multi-file upload. Plain forms, so it works without JavaScript and by keyboard; no drag and drop. |
| CSS/tokens | Gallery, viewer and manager styles; `--color-backdrop` and size tokens. |

## Limitations / deviations
- The roadmap names the photo field `publicId`; the old code called it `filename`, hence migration 004.
- WebP is accepted in addition to PNG and JPEG (Cloudinary supports it; phones and editors produce it). GIF, SVG, HEIC and PDF are refused.
- The limit of 10 is checked in code and by the model's validator when saving, not as one atomic database operation: two uploads at the very same moment by the same host could pass 10. One owner editing one listing makes that unlikely; the model validator rejects the next save.
- No drag-and-drop reordering yet (buttons instead); the creation wizard (P04-T02) and the new edit flow (P04-T04) will reuse `images.js`.
- Cards still use the stored cover URL; only the gallery, the edit page and the helper apply size presets so far (card and home presets come with P18-T01).
- Photos are not re-checked for pixel size or EXIF location data; Cloudinary strips metadata on delivery but the original upload keeps it (P18-T01).
- Uploads to Cloudinary were verified against the jest mock only, never against the real service.
