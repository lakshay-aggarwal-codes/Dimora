## Endpoints
JSON (401 JSON when signed out; POST bodies are form-encoded with `X-CSRF-Token`, like every POST here):
`GET /api/conversations?page=`, `GET /api/conversations/:id/messages?before=<messageId>`, `POST /api/conversations/:id/messages` (`body`), `POST /api/listings/:id/conversations` (201 new / 200 existing), `POST /api/reservations/:id/conversation`.
Pages: `POST /listings/:id/contact` (redirects to the thread), `GET /conversations/:id`, `POST /conversations/:id/messages`.

## Behaviour
- **Participants only.** The conversation's guest and host. An admin, an outsider, an unknown id and a malformed id all get the same 404. A suspended participant gets 403.
- **Contact host** needs a public listing (draft, unpublished, deleted, unknown = 404), not your own listing (403), and an active host (409 otherwise). One general conversation per (listing, guest); one per booking (either side may open it; an outsider or admin gets the booking's 404). Two clicks at once make one conversation (unique `threadKey`; the loser re-reads).
- **Suspended accounts.** Nothing is started or sent while either account is not active (409); the thread page then shows no reply form.
- **Message text.** Plain text, trimmed, line breaks kept (`\r\n` becomes `\n`), tabs allowed, other control characters refused, 1-1000 characters; longer is refused with the length, never cut. Stored as typed; the page prints it escaped (`<%= %>`, CSS `white-space: pre-wrap`). JSON carries it as a JSON string.
- **Unread counters.** Sending raises the other side's counter by 1; opening the thread (page or `GET .../messages`) sets the reader's own to 0.
- **List.** Only the member's conversations that already have a message, newest message first, with the member's own unread count. A conversation started with "Contact host" but never written in is not listed (nobody is bothered by an empty thread).
- **Thread paging.** Newest 50, oldest first; `nextBefore` is the id to pass as `before` for the page of earlier messages (ordered by message id, so equal timestamps cannot reorder them).

## Limitations
- No inbox list page, unread dots, mobile layout or polling: P11-T03. The thread page is deliberately bare.
- No notification or email when a message arrives (P11-T04/T05).
- Reporting a message and the admin's route into a reported thread: `services/reports.js` still refuses kind `message`; wiring it belongs to a P12-T04 follow-up. Until then admins cannot read conversations at all.
- The rate limit is per server process (like the report limiter); no daily cap in the database.
- The trip page has no "Message host" link yet; the API endpoint for a booking thread exists.
- The app has no JSON body parser, so the JSON endpoints take form-encoded POSTs.
- Messages are never deleted (not even when an account is deleted); a retention rule is not specified.
- The test helper `tests/helpers/fakeCollection.js` supports only the query shapes the service uses; query shapes were not run against MongoDB.
