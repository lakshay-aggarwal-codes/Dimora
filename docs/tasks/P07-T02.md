## Behaviour
- `reserveNights`: nights are validated (non-empty array, at most 366, date-only, no duplicates), sorted ascending, inserted with `insertMany(..., { ordered: true })` with pre-generated `_id`s. Duplicate key (11000) means a night is held: the attempt's rows are deleted and a `ConflictError` (409, code `nights_unavailable`, `conflictingDates`) is thrown. Any other error also rolls back, then is rethrown; if the rollback itself fails the error says so and keeps `cause`/`cleanupError`.
- Expired hold takeover: on the first collision, conditional `deleteMany` of rows for the requested nights with `holdExpiresAt < now`; if something was deleted, one retry. Confirmed rows (no hold) and live holds are never taken over.
- `holdExpiresAt` must be a future Date or null (confirmed reservations and blocks have none).
- `releaseNights(sourceId)`: deletes all rows of that source; returns `{ released }`; idempotent.
- `availableRanges(listingId, from, to)`: free runs inside `[from, to)` (`to` exclusive, at most 400 nights); expired holds count as free; each item `{ from, to, nights }`.
- Bad arguments (non-date-only dates, bad ids, wrong source kind) are `TypeError`: callers are services, not users.

## Limitations
- Cannot confirm yet: that Mongoose's `insertMany(..., { ordered: true })` throws an error with code 11000 on the duplicate (assumed from the driver contract; the DB tests cover it), and that 20 consecutive runs pass.
- The unique index is created by Mongoose `autoIndex` (on by default). The race test calls `StayNight.init()` first. A production deploy should let the index finish building before taking bookings (an empty collection builds instantly).
- No `confirmNights` (clearing `holdExpiresAt` when a host accepts) and no sweeper: they belong to P07-T05 and P07-T07.
- The ledger is not wired to any route or reservation yet.
- Verify command differs from the card: the suite is `ledger.db.test.js` (repo naming convention for database suites).
