## Decisions
- **Every absolute address comes from `APP_BASE_URL`**, never the `Host` header (tested with forged `Host`/`X-Forwarded-Host`).
- **`robots.txt` is not enough**, so private pages also say `noindex`. Disallowing `/api/` and `/admin/` is the card's minimum; the rest of the list is private areas that exist today (account, host, trips, wishlists, compare, reports, login, signup, conversations, notifications, listing new/edit/checkout/images).
- **Canonical ignores filters on purpose** (dates, guests, sort show the same stays); `?page=N` keeps its own address because page 2 is different content. Search results pages are therefore indexable; they are not in the sitemap.
- Sitemap holds only the five public pages and listings. Profiles (`/users/:id`) are public but not listed.
- `og:type` is `website` for every page (no schema-specific type).

## Limitations
- No `queryPlans` entry for the sitemap query (a filter on `status`/`deletedAt` with a sort by `_id`, 5,000 at most). It is a candidate for the index review if the collection grows.
- More than 5,000 listings need a sitemap index; not built.
- Nothing is submitted to Google/Bing; do it in their webmaster tools after deploying.
- `lastmod` is the listing's `updatedAt`, which also changes on rating updates.

## Owner's manual steps
1. Set `APP_BASE_URL` to the public address; open `/robots.txt` and `/sitemap.xml` on the deployed site.
2. View source of a listing page: canonical and `og:*` present; of `/login`: `noindex`.
3. Paste a listing link into a link-preview tool (WhatsApp, Slack) to see the card with the photo.
4. Add the site and sitemap in Google Search Console.
