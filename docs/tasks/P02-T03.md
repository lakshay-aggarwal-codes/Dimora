# P02-T03 - Profile pages (Q34)

Date: 2026-10-17 - Deps: P02-T01 (user model v2) and P04-T03 (image service), done. No new dependency, no migration (the user model already had `displayName`, `avatar` and `bio`).

## What was added
| Item | Notes |
|---|---|
| `GET /users/:id` | `src/controllers/profile.js` `show` -> `views/users/profile.ejs`. Data from `src/services/profile.js`: the user is read with `select("username displayName avatar bio createdAt")` and `status: "active"` only, so the email, hash, salt, role and status are never loaded into the page. |
| Page content | Display name, `@username`, avatar (or the first letter), bio (line breaks kept, escaped), "Member since October 2026" (India time), counts of public listings (`publicListingFilter`) and reviews written, and up to 5 recent reviews that link to a listing a visitor could open. The owner sees "Edit your profile". |
| `GET/PUT /account/profile` | Login required; no id in the URL, so it always edits `req.user`. Multipart (the CSRF token is in the query, as for the other upload forms). `src/validation/profile.js`: display name <= 60, bio <= 500, no control characters, line breaks normalised; any other field is refused. |
| Photo | `upload.single("avatar")`, then `assertValidImage` (the first bytes, so a fake .jpg fails) and a 2 MB cap (the 5 MB multer limit still applies first, answer 413). Uploaded with the existing `uploadBuffer`; the previous photo is deleted from Cloudinary only after the new profile is saved; if saving fails the new upload is deleted. "Remove my photo" clears it. |
| Misc | `avatar` preset in `src/utils/imageUrl.js` (256 px square, face-aware crop), `views/partials/avatar.ejs`, "My profile" in the account menu, CSS in `components.css`. |
| Tests | `profile.validation`, `profile.service` (unit); `profile.db` (real MongoDB: only the owner edits, email/hash/salt never printed, 404 cases, photo checks and cleanup). |

## Decisions
- A deleted or suspended member's page is a 404, the same as an unknown id, so the URL does not tell a visitor which accounts exist.
- Usernames were already public on reviews, so `@username` is shown beside the display name.
- The profile form has no email field at all; changing the email belongs to P02-T05 (verification).

## Limitations
- Review authors on listing pages are not links to profiles yet (it touches the review markup that other tests pin; a small follow-up).
- "Reviews written" counts all of a member's reviews; the recent list omits those on listings that are not public. Review model v2 (P12-T01) adds a listing reference and makes this exact.
