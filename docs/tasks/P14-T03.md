## Behaviour
- **Queues** (20 per page, `?filter=reported|new|suspended`, anything else = reported; the page number is read only if it is plain digits):
  - *Reported*: listings with at least one OPEN report (P12-T04), most open reports first, then the most recent report; deleted listings are left out.
  - *New*: `published`, not deleted, `moderation.reviewedAt` not set, oldest first. **Every listing that was published before this task starts in this queue**; "Mark as reviewed" takes it out. Suspending or restoring also counts as a review.
  - *Suspended*: status `suspended`, not deleted, latest first. A listing hidden because its host's account is suspended (P14-T02) is labelled "with the host's account".
- **Listing page**: host (link to the account page), place, price, number of photos, review state, link to the public page, description excerpt (400 characters), open reports (reporter, reason, details), the current suspension (who, when, reason), the last 10 audit rows about the listing. The host's email is never selected. All member-typed text is printed escaped.
- **Suspend** (`listing.suspend`): reason required, 5-500 characters, shown to the host and written to the audit log. Only a `published`, not-deleted listing; drafts and unpublished listings are not visible to guests anyway. One `updateOne` filtered on `status: "published"`, so two admins at once cannot both succeed (the loser is told to reload). The listing leaves search, the public page and booking at once (the same `status` the whole app already filters on); the host and admins can still open it.
- **Restore** (`listing.restore`): reason required. Only a `suspended` listing WITHOUT `hiddenByOwnerSuspension` (those come back when the host is reinstated); filtered in the update as well. It becomes `published` again and the suspension fields are cleared (the audit log keeps the history).
- **Mark reviewed** (`listing.review`): note optional (5-500 characters when given), only where `reviewedAt` is not set.
- **Refusals** (short or missing reason, malformed or unknown id, deleted listing, wrong status, a lost race) flash a message, change nothing and write **no** audit row (`AdminRefusal`). Members and visitors get the ordinary 404 for every route.
- **Host side**: `/host/listings/:id/status` shows a red notice with the moderators' reason (or "hidden because your account is suspended"), says guests cannot see it, hides the publish/unpublish buttons (publishing a suspended listing was already refused by the lifecycle service; the page used to offer a button that failed). The calendar was already closed for suspended listings (P07-T03) and accepting a request for one already answers 409 (P09-T02).

## Not in this task
- **Notifying the host** (needs P11-T04). Until then the host finds the reason on the listing's status page; nothing is sent.
- **Closing reports** (resolve/dismiss) and hiding reviews: P14-T04. Reports stay open when a listing is suspended; the queue still shows them under "Suspended" with their count.
- **Existing bookings on a suspended listing** are left as they are (not cancelled, not refunded): a moderation decision about a listing is not a decision about a guest's trip. An admin who wants them cancelled has no admin cancel flow yet (not in the roadmap); the host can cancel (P09-T03).
- **Suspending a host's account** (P14-T02) still does not decline that host's pending requests (its report says to add that now that reservations exist); that is unchanged.

## Manual checks (owner, `npm run dev`; you need an admin account from `npm run make-admin`)
1. `/admin` -> "Listing moderation": three tabs. Your existing listings are under "New".
2. Open a listing, "Mark as reviewed": it leaves "New"; the page then shows no such form.
3. As a member, report a listing (`/reports/new?kind=listing&id=...`); as the admin it appears under "Reported" with count 1 and the report's reason and details on its page.
4. Suspend it with a reason: guests get a 404 for it, it disappears from `/listings`; as its host, `/host/listings/<id>/status` shows the reason and no publish button; `/admin/audit` has a `listing.suspend` row with the reason.
5. Try to suspend it again, or with a 3-character reason: a message, no new audit row.
6. Restore it with a reason: it is public again; audit row `listing.restore`.
7. Suspend a host's account (`/admin/users`), then open one of their listings in the Suspended tab: it says it comes back when the account is reinstated and has no restore form.
