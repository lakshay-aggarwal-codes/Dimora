## Rules implemented
See `docs/AUTHORIZATION.md`. Decisions where the roadmap was silent: admins may delete any listing and review but not edit a host's listing; suspended/deleted accounts are denied everything; accounts with no `status` count as active; a review must belong to the listing in the URL (otherwise 404); a missing listing/review is 404 before any permission check.

## Behaviour changes
- A logged-in non-owner on edit/update/delete now gets a **403 page** (roadmap), not a redirect with a flash message. A listing with no owner: 403 (admin may delete).
- `GET /listings/new`, `POST /listings` and review creation now also refuse suspended accounts (403).
- `/listings/<any id>/reviews/<review id>` no longer works across listings.

## Bug found by the tests
`idOf` initially treated an object without `_id` as the string "[object Object]", which made `{ role: "admin" }` count as an active user. Fixed in `src/policies/shared.js` (such objects have no id; user must have `_id`).
