# P06-T04 - Search map and list/map toggle (Q42)

Deps: P06-T02 (done, Q40), P05-T02 (done, Q36).

## What changed
- `GET /api/search/map` (`src/routes/api.js`, mounted at `/api` in `src/app.js`; handler `mapData` in `src/controllers/search.js`). Query: `bbox=west,south,east,north` plus the same filter names as `/listings` (`dest`, `in`, `out`, `guests`, prices, type, amenities, category...). Response: GeoJSON `FeatureCollection` of at most 200 points plus `meta {total, returned, capped, cap, message}`; `Cache-Control: no-store`; no login needed (public data only).
- Privacy: a feature's geometry is always `publicGeometry` (P06-T02). The query projection asks for title, nightly price, currency and `publicGeometry` only: the precise point, the address and the host never leave the database for this endpoint.
- `src/utils/bbox.js`: `parseBbox`. Only four plain numbers (an array/object/repeated parameter is refused). Boxes across the antimeridian become two boxes; a box 360 degrees or wider covers every longitude. Longitudes already inside +-180 are not touched.
- `src/services/mapSearch.js`: `searchMap`, `bboxCondition` (longitude/latitude ranges on `publicGeometry.coordinates.0/.1`, no spherical polygon, so the box does not curve), `toFeature`. Cap `MAP_RESULT_CAP = 200`, newest first.
- `src/services/listingFilter.js`: the validated-params -> filter -> night-ledger exclusion step that used to sit in the page controller, now shared so the list and the map always show the same stays. The page behaves as before.
- `views/listings/index.ejs`: toggle button (hidden), the `#search-split` wrapper around the existing results region (its tag is unchanged), the hidden map panel, `data-listing-id` on every card, the new script tag. `mapQuery` (the page's validated filters, no `page`) goes to the map as `data-query`.
- `public/js/searchMap.js`: builds the map when first opened; clustered source; cluster circles with counts; price labels; "Search as I move the map" (opt-in, off, 400 ms pause); "Search this area" after a manual move when the opt-in is off; card <-> price highlight; popup from text with a same-site link; failure messages that point to the list; 10 s load timeout. Colours are read from the CSS tokens.
- `public/css/components.css`: panel, tools, highlight outline; phone = list or map, `>= 992px` = list left, sticky map right.

## Limitations
- Never seen in a browser. Mapbox style `streets-v12` and its glyph fonts (`DIN Pro Medium`) are assumed available to the public token; if the labels do not show, say so.
- No spatial index for the box (plain ranges). Fine for thousands of listings; P18-T02 should look at it.
- A listing without `publicGeometry` (saved before migration 007 ran) is not on the map.
- When more than 200 stays match, the first 200 by newest are shown, not the nearest to the centre.
- Hover links a card and a price label that is not inside a cluster; on touch there is no hover (a tap opens the popup).
- The list is still the 12-per-page page; the map can show up to 200 stays.
- `sort`, `minRating` and category behaviour are whatever the page does today (Q37/Q38 are not listed as done in PROGRESS.md).

## Owner steps (browser, your public token)
1. `npm test` and `npm run lint` once.
2. Open `/listings`: a "Show map" button appears. Click it: map with clusters and prices; clicking a cluster zooms in; clicking a price opens a popup with a link.
3. On a wide screen: hover a card, its price gets a halo on the map; hover a price, its card gets an outline.
4. Tick "Search as I move the map", pan: results reload; untick, pan: "Search this area" appears.
5. Search `?dest=Goa`: the map fits Goa. Search something with no match: "No stays in this area."
6. On a phone width: the button switches between the list and the map.
7. DevTools > Network > Offline, open the map: the message says the list shows the same stays.
8. Open `/api/search/map?bbox=-180,-60,180,70` in the browser and search the text for a street address: none.
