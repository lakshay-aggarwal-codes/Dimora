# P01-T03 — App/server split and `src/` move (Q6)

Date: 2026-10-14 · Node v22.22.2

## What changed
**Moves (no content change, done with `git mv` by the run block, history kept):**
`models/` → `src/models/`, `utils/` → `src/utils/`, `controllers/review.js` and `controllers/user.js` → `src/controllers/`, `schema.js` → `src/validation/index.js`, `init/data.js` → `scripts/seed-data.js`.

**Moves with small edits (included in the zip):**
| Old | New | Edit |
|---|---|---|
| `app.js` | `src/app.js` | Rewritten as `createApp({ config, sessionStore })`; env loading, DNS, `mongoose.connect` and `listen` moved to `server.js`. Middleware order, session options, routes, 404 and error handler are identical. Paths to `views/` and `public/` now go up one level from `src/`. |
| `cloudConfig.js` | `src/config/cloudinary.js` | No longer reads env when required; exports `configureCloudinary()`, which `createApp()` calls. |
| `middleware.js` | `src/middleware/index.js` | `require` paths only. |
| `routes/*.js` | `src/routes/*.js` | `require` paths only. |
| `controllers/listing.js` | `src/controllers/listing.js` | Mapbox geocoder built on first use (`getGeocodingClient`) instead of at require time; new export `initGeocoding()`. |
| `init/index.js` | `scripts/seed.js` | `require` paths and data file name only (still the legacy script; P01-T06 rewrites it). |

**New:** `server.js` (entry point), `tests/unit/app.smoke.test.js`.
**Edited config:** `package.json` (`main`/`start`/`dev` → `server.js`, `seed` → `scripts/seed.js`), `.prettierignore` (`init/data.js` → `scripts/seed-data.js`).

## Behaviour
- `require("./src/app")` has no side effects: no env read, no DB connection, no port. Verified in a child process with an empty environment.
- `npm run dev` / `npm start` behave as before: same startup order (env check → DNS → app built → `mongoose.connect` → `listen`), same messages, same exit on invalid env or failed connection.
- A malformed `MAPBOX_SERVER_TOKEN` still stops the server at boot (`server.js` calls `initGeocoding()`); only the lazy build differs for code that imports the controller without `server.js`.
- `createApp()` with no arguments reads `process.env` via `loadEnv()`; tests pass a config object and a `MemoryStore` instead.

## Verification (sandbox)
- `npm ci` OK (lockfile in sync). Before the change: `npm run lint` clean, `npm test` 28/28.
- After: `npm run lint` clean; `prettier --check` clean on new/edited JS; `npm test` 32/32 (28 existing + 4 new).

## Deviations / notes
- File names inside `routes/` and `controllers/` are kept (`listing.js`, `review.js`, `user.js`), not renamed to `listings`/`reviews`/`users` (§9): task cards for P01-T05–T07 name the current file names, and this task is meant to be mechanical.
- `middleware.js` and `schema.js` became `index.js` inside `src/middleware/` and `src/validation/` so existing `require("../middleware")` specifiers keep their shape; later tasks split them.
- `init/` → `scripts/seed.js`: the legacy seed script was moved, not replaced by a stub, so `npm run seed` still means what it meant (broken per D-05).
- `docs/BASELINE.md` still mentions `init/` and `app.js` (it describes the pre-move state).
