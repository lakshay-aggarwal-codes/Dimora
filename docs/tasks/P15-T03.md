## Behaviour
- Data is what `listing.nearby` already holds; `neighborhoodFor` (P15-T02) does the selection and rounding, so the comparison can never show more than the listing page: distances from the approximate point, nearest 50 m, "straight-line", no coordinates.
- Cell: name (or kind if unnamed), kind, distance. "None found nearby" = data fetched, category empty. "Not available yet" = that stay has nothing stored. Dash = stay no longer public.
- Rows and the note appear only if some live stay has stored data. Note: "(c) OpenStreetMap contributors, saved on / between <dates>. They may be out of date." (attribution required by the data licence).
- Unchanged: prices, quotes, currency block, amenity matrix, URL format.

## Evidence
- **Run here:** `node --check`; the pure helpers executed directly (nearest pick, rounding, no-data null, section dates).
- **Not executed:** Jest, ESLint, EJS rendering (no `node_modules`/network).

## Manual checks
1. `npm test`.
2. Compare two listings that have nearby data (publish one, or the host presses "Refresh nearby places"): both rows show names and distances; the note shows the dates.
3. Add a listing with no data: its cells say "Not available yet".
4. View source: no latitude/longitude of any nearby place.

## Limitations
- Demo listings from `seed:demo` have no stored nearby data until fetched, so the rows are absent for them.
- No "closest" highlight or ranking; no other categories (food, park, ...) in the comparison.
