## Eligibility (each with its own message and code)
| Case | Answer |
|---|---|
| Rating not a whole 1-5, comment empty or over 2000 characters | 400, nothing looked up |
| Signed out, suspended | 403 `account_not_active` |
| Stay missing, somebody else's, of another listing than the URL's, malformed id | the same 404 |
| The author is the host of the place | 403 `own_listing` |
| Stay not `completed` (pending, confirmed, declined, expired, cancelled) | 409 `stay_not_completed` |
| Today in the stay's time zone is after check-out + window | 409 `review_window_closed` (the last day is allowed) |
| Already reviewed | 409 `already_reviewed` (also when 10 requests race: the unique index lets exactly one in) |
Host deletes the listing after the stay: the stay can still be reviewed; the review keeps `listing` and `listingSnapshot`.

## Run order (important)
1. `npm run migrate:dry` and read the counts (reviews scanned, marked legacy, linked to a listing, without dates).
2. `npm run migrate`.
3. Start the app. Until the migration has run, old reviews load but are not marked legacy and have no `listing`.
A review that no listing holds in its `reviews` array keeps no `listing` (listed in the dry-run counts as `withoutListing` minus the linked ones).

## Limitations
- No review prompt on "Your trips" and no new star input (P12-T02). Until then the form is on the listing page only.
- Rating aggregates still come from `listing.reviews`, to which a new review is pushed after it is stored; if that push fails the review exists but is not listed (P12-T02 replaces the array with a query and atomic counters).
- Deleting a review (author or admin) frees its stay to be reviewed again inside the window.
- `crestedAt` is dropped from the model; old documents lose it through the migration only.
- Reviews of a hard-deleted listing remain in the collection with no page showing them yet.
