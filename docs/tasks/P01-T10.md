## Deviations / extra fixes (same root cause or found while verifying)
1. **`locals.x` does not work in views.** Under ejs-mate, `locals` inside a template is ejs-mate's own `{ blocks }` object, so `locals.cspNonce` and `locals.mapPoint` were always empty. Effects (both from earlier tasks): every inline `<style>`/`<script>` got `nonce=""` and would be blocked by the Q12 CSP in a browser, and the detail-page map never rendered. Fixed with `typeof x !== 'undefined'` checks in `navbar.ejs`, `listings/index.ejs` (2), `listings/show.ejs` (1). `csrf.views.test.js` now fails if any view uses `locals.` again. (This also fixes the Q12 test "every inline script and style carries this request's nonce", which was failing.)
2. `tests/integration/security.test.js`: the cookie test asserted `Max-Age=604800`; express-session sends the lifetime as `Expires`, so the assertion is now `Expires=`.
3. Roadmap path `views/partials/csrf.ejs` → `views/includes/csrf.ejs` (repo convention).

## Behaviour to know
- A form rendered before login or logout is rejected afterwards (those regenerate the session): the visitor sees the 403 page asking to reload. A normal flow (page → submit) is not affected. Back button to a page of the same session keeps working (the token is stable per session).
- The 403 happens before the login rate limiter, so requests without a token do not use up the 5-attempt budget.
- Multipart forms: the token is in the URL (`?_csrf=`). Request logs strip the query string; the `Referrer-Policy` sends only the origin cross-site.
- For `fetch`: `headers: { "X-CSRF-Token": document.querySelector('meta[name="csrf-token"]').content }`.
