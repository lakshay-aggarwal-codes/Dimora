## What was found and changed
| Finding | Change |
|---|---|
| `--duration-slow` was **700 ms** (used by the star-rating hover) | now 300 ms. Rule: no feedback animation over 300 ms |
| The category strip (`.filter-container`) had `scroll-behavior: smooth`, and the reduced-motion block only reset `html` | the block now resets `.filter-container` too; a test fails for any smooth-scrolling element not named there |
| The search map's own moves (`map.easeTo` on a cluster) used Mapbox's default of **500 ms**, and ignored the preference | `MOVE_MS` = 250 ms, 0 under "reduce motion" (`matchMedia`), stated on every move; a page without `matchMedia` is treated as no preference |
| Price panel: only the words "Checking the price…" while waiting | plus grey skeleton blocks shaped like the price lines (`aria-hidden`, so the live region still speaks only the words), `aria-busy` on the region until any answer arrives |
| Search map: blank until the stays arrive | `#search-map.is-loading` grey pulse, removed on success, failure and "map unavailable" |
| Breakpoints `max-width: 992px` and `576px` (Bootstrap's are `991.98px` and `575.98px`: the old ones overlapped the next breakpoint by 1 px) | changed; a test allows only Bootstrap's set |
| (checked, nothing to change) | viewport meta without a zoom lock; `img { max-width: 100% }`; every one of the 8 views with a table wraps it in `.table-responsive`; the only fixed width above 320 px is the month calendar, which scrolls inside its own wrapper; no `100vw` outside `min()`; form text is 1rem |

The loading pulse repeats for 1.2 s and is the one animation over 300 ms: it is a loading indicator, not feedback, and it stops under "reduce motion". `--duration-loading` exists for it and the test lets only the skeleton selectors use it.
