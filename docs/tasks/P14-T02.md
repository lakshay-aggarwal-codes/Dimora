## Behaviour
- **Search**: text matched against username, email and display name as plain text (regex characters escaped), case-insensitive, 100 characters at most; optional status; 20 per page, sorted by username. Only plain-string query values are used.
- **Account page**: status, role, joined date, listings by status, reviews written, reservations (0 for now), last 10 admin actions on that account. Password hash and salt are never selected.
- **Suspend** (reason required, 5-500 characters, same for reinstate):
  1. refused, with nothing changed, for: no/short reason, unknown or malformed id, own account, account not `active`, last active admin;
  2. `status` set with `updateOne({_id, status:"active"})`, so two admins acting at once cannot both succeed;
  3. the host's `published`, not-deleted listings become `suspended` with `hiddenByOwnerSuspension: true` (drafts and unpublished ones are not public anyway; moderation-suspended ones are left alone);
  4. the account's sessions are deleted from the store: connect-mongo by one `deleteMany` matching the passport user in the stored JSON (username JSON-escaped and regex-escaped, so `ann` never matches `ann2`), `MemoryStore` by walking `all()`; a store that can do neither is an error, never a silent skip;
  5. one audit row `user.suspend` with reason and details (username, role, from/to, listings hidden, sessions deleted). No email, hash or salt.
- **Reinstate**: only from `suspended` (a `deleted` account cannot be reinstated); listings with the flag go back to `published` and lose the flag; audit row `user.reinstate`.
- Login of a suspended account was already refused (P02-T01/T02); the policies already deny it everything.

- Reinstating also requires a reason (the roadmap says "suspend/reinstate with required reason").
- "Host notified" is not part of this task (that is P11).

## Limitations
- Session deletion happens once, at suspension. There is no per-request status check as a backstop, so a session created in the same instant as the suspension would survive until its next request; the policies still deny it everything.
- Search is a case-insensitive "contains" match without an index (fine for this scale).
- The viewer has no filters (P14-T05).
