## Overpass usage policy (read 2026-10-25, official manual and OSM wiki)
Shared public servers; stay well under about 10,000 queries and 1 GB a day; about 2 slots per IP; HTTP 429 when the rate limit is hit; declare `[timeout:]`/`[maxsize:]`; identify the application in the User-Agent. Each refresh is 7 queries, run one at a time; they happen only at publish, on a host's button (1 per listing per day) and in the retry job.

## Deviations from the roadmap
- Distances are measured from the **public (approximate) point**, not the precise one. The search area is still centred on the precise point. Reason: distances from the precise point to several places with known positions would let anyone compute the home's position and undo the approximate location (P06-T02). Candidates come from the true surroundings; only the stored distances use the public point.
- 7 queries (one per category) instead of one big query, so a dense category cannot use up the result cap of the others.
- The host button and the publish hook run in the background; the host sees the result after reloading the status page.
- "Recorded fixture responses": the fixture answers in the test are written by hand in Overpass's JSON shape (`out center tags`), not recorded from the live service.
- "Names escaped in the view": covered for the host status block; the guest-facing view is P15-T02 and must also use `<%= %>`.

## Limits
- Concurrency 1 is per process; several app instances each keep their own queue (the daily limits still hold at this volume).
- The retry job runs in every instance; two instances may retry the same listing close together (the 5-minute attempt throttle makes the second a no-op).
- Same-name places (chains) collapse to the nearest one per category.
- Listings published before this task have no nearby data until a host presses the button or you run `npm run nearby:refresh`.

## Manual checks (needs internet; set `NEARBY_CONTACT` in `.env` first)
1. `npm run nearby:refresh -- --limit 3`: each listing reports `updated (N places)`; run it again within 5 minutes: `throttled`.
2. Host status page of one of them: counts per category, names, date; the button is disabled with "Available again on ...".
3. Publish a new listing: publishing works at once; reload its status page after a minute: places are there.
4. Unplug the network (or set `OVERPASS_URL` to an unreachable https address), press the button on another listing: status page says it will retry automatically; old data, if any, stays.
5. Open a listing's public page with the network tab open: no request to overpass anywhere (the browser never calls it, and the server only reads stored data).
