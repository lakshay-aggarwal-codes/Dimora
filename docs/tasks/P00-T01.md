Date: 2026-10-14 · Node used: v22.22.2 · npm 10.9.7

## Files changed
- `package.json` — removed `multer-storage-cloudinary`; added `"engines": { "node": ">=20.19.0" }`.
- `package-lock.json` — regenerated from the updated `package.json` (`npm install --package-lock-only`, then verified with a clean `npm ci`).
- `cloudConfig.js` — now exports `cloudinary`, `upload` (multer memory storage) and `uploadToCloudinary` (middleware streaming `req.file.buffer` to Cloudinary, folder `dimora_DEV`). It sets `req.file.path` (= `secure_url`) and `req.file.filename` (= `public_id`), the same fields the old package set, so `controllers/listing.js` is unchanged.
- `routes/listing.js` — imports `upload`/`uploadToCloudinary` from `cloudConfig.js`; `uploadToCloudinary` added after `upload.single(...)` on `PUT /listings/:id`.
- `docs/PROGRESS.md`, `docs/tasks/P00-T01.md` — new.

- `main` still points at a missing `index.js`, and no `start`/`dev` script exists yet (D-17 → P01-T02).
- `POST /listings` still has no upload middleware (D-02) — out of scope, fixed in Q9 (P01-T05).
- Missing `MAP_TOKEN` still crashes at require time (formalised in P01-T01).
