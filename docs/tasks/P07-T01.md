## API (`src/utils/dates.js`)
A "date-only Date" is a `Date` at exactly 00:00:00.000Z.
- `parseDateOnly(str, label?)` strict `YYYY-MM-DD` (4-digit year 1000-9999, ASCII digits, no spaces/time/newline, real calendar date); throws `ValidationError` (400) `"<label> must be a valid date in YYYY-MM-DD format."`. `tryParseDateOnly(str)` returns `null` instead. Non-strings are invalid.
- `formatDateOnly(date)`, `addDays(date, n)`, `isDateOnly(value)`: pure UTC arithmetic, so DST cannot shift a date.
- `compareDates`, `isBefore`, `isAfter`, `isSameDate`.
- `nightsBetween(checkIn, checkOut)`: integer; check-out <= check-in throws `ValidationError` "Check-out must be after check-in.".
- `eachNight(checkIn, checkOut, {maxNights = 90})`: array of occupied nights (check-out excluded); over the cap throws before building the array.
- `todayIn(timeZone = "Asia/Kolkata", now = new Date())`: today's calendar date in an IANA zone (via `Intl.DateTimeFormat`); `now` is injectable; unknown zone = `ValidationError`.
- `BOOKING_WINDOW` (frozen): `MIN_ADVANCE_DAYS: 0`, `MAX_HORIZON_DAYS: 365`, `MAX_STAY_NIGHTS: 90`. `bookingWindow(today)` returns the earliest/latest check-in; `assertBookableDates({checkIn, checkOut, today})` returns the night count or throws a rule-specific `ValidationError` (past check-in, beyond 365 days, bad order, over 90 nights).
- Passing something that is not a date-only Date to these functions is a programming error and throws `TypeError` (a 500, never a user message).

## Decisions
- Lives in `src/utils/dates.js` (the card says `utils/dates.js`; the repo moved to `src/` in P01-T03).
- Minimum advance is 0 days (same-day check-in allowed) as the default constant; host-set advance notice and same-day cut-off are P07-T06.
- Latest check-in = today + 365 days; the check-out of such a stay may fall after that date.
- Years below 1000 are rejected (`Date.UTC` would map `0050` to 1950).
- "Policy dates" from ADR-003 (cancellation cut-offs) are not here: they belong to P09-T03 and will build on `todayIn`/`addDays`.
