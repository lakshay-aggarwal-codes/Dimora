## Decisions
- **Destination is "starts with", by comma part**, not a free-text contains: it is what an index can answer. "Panaji, Goa" and "goa" work; "anaji" does not; "goa india" (no comma) looks for one key starting "goa india" and finds nothing. Autocomplete (P05-T06) and the destination box in P05-T02 should offer the comma form.
- **`keywords` is separate from `destination`** (text index versus place keys); the navbar's single `search` box will map to `destination` in P05-T02.
- Invalid parameters are reported, not fatal: the caller decides whether to show a message.

## Limitations
- Not wired to the pages: `/listings` and the home page still list as before (P05-T02 adds the URL parameters, P05-T03 sorting and paging).
- `updateOne`/`bulkWrite`/`insertMany` skip the validate hook: anything that writes an address that way must set the keys (the seed does; migration 006 repairs the rest).
- No availability (dates) filter yet: that needs the ledger (P07).
- A prefix on the whole key: "john" does not find "st john".
